# Example: spec→code Morphism Chain

This document traces a single route through all 4 layers of the algebraic pipeline.

## Input: Markdown Spec (Layer 0)

```markdown
# User Service API

A web service for managing users.

## API Endpoints

- **GET** `/api/users` - List all users
- **POST** `/api/users` - Create a new user
```

---

## Layer 1: Markdown → NCL (μ_spec→ncl)

The `spec_md_to_ncl.rs` parser extracts structured data:

```nickel
# spec.ncl
{
  iu_id = "user-service",
  template = "nodejs-express",
  project_name = "user-service",
  version = "0.1.0",
  description = "A web service for managing users.",
  
  routes = [
    { 
      method = "GET", 
      path = "/api/users", 
      handler = "listUsers",
      description = "List all users" 
    },
    { 
      method = "POST", 
      path = "/api/users", 
      handler = "createUsers",
      description = "Create a new user" 
    }
  ]
}
```

**Morphism:** `μ_spec→ncl : Markdown → NCL Record`

---

## Layer 2: NCL → BundleConfig (μ_ncl→config)

The `expr_bundle.rs` parser converts NCL to Rust structs:

```rust
// BundleConfig
BundleConfig {
    project_name: "user-service".into(),
    version: "0.1.0".into(),
    project_description: Some("A web service for managing users.".into()),
    
    routes: vec![
        RouteConfig {
            method: "GET".into(),
            path: "/api/users".into(),
            handler: "listUsers".into(),
            description: "List all users".into(),
        },
        RouteConfig {
            method: "POST".into(),
            path: "/api/users".into(),
            handler: "createUsers".into(),
            description: "Create a new user".into(),
        }
    ],
    ..Default::default()
}
```

**Morphism:** `μ_ncl→config : NCL Record → BundleConfig`

---

## Layer 3: BundleConfig → Expr (μ_config→expr)

The `generate.rs` constructs an Expr term (algebraic structure):

```rust
// Build environment
let env = Env::new()
    .extend("project_name".into(), 
            Literal::Str("user-service".into()));

// Build routes as Expr Literal
let routes_literal = Literal::List(vec![
    Literal::Record(vec![
        (Arc::from("method"), Literal::Str("GET".into())),
        (Arc::from("path"), Literal::Str("/api/users".into())),
        (Arc::from("handler"), Literal::Str("listUsers".into())),
        (Arc::from("description"), Literal::Str("List all users".into())),
    ]),
    Literal::Record(vec![
        (Arc::from("method"), Literal::Str("POST".into())),
        (Arc::from("path"), Literal::Str("/api/users".into())),
        (Arc::from("handler"), Literal::Str("createUsers".into())),
        (Arc::from("description"), Literal::Str("Create a new user".into())),
    ]),
]);

// Wrap in Expr for evaluation
let expr = Expr::Lit(routes_literal);
```

**Morphism:** `μ_config→expr : BundleConfig → Expr`

**The Expr structure (algebraic term):**
```
Expr::Lit(
  List([
    Record([("method", Str("GET")), ("path", Str("/api/users")), ...]),
    Record([("method", Str("POST")), ("path", Str("/api/users")), ...])
  ])
)
```

---

## Layer 4: Expr → Code (μ_expr→code)

The `eval()` function evaluates the Expr to a Literal, then generates code:

```rust
// Evaluate
let eval_config = EvalConfig::default();
let result = eval(&expr, &env, &eval_config)?;

// result is now: Literal::List([Literal::Record(...), Literal::Record(...)])

// Generate code by pattern matching on Literal
fn generate_route_handler(route_lit: &Literal) -> String {
    if let Literal::Record(fields) = route_lit {
        // Extract fields
        let method = fields.iter()
            .find(|(k, _)| k.as_ref() == "method")
            .and_then(|(_, v)| match v {
                Literal::Str(s) => Some(s.as_ref()),
                _ => None
            })
            .unwrap_or("get");
        
        let path = fields.iter()
            .find(|(k, _)| k.as_ref() == "path")
            .and_then(|(_, v)| match v {
                Literal::Str(s) => Some(s.as_ref()),
                _ => None
            })
            .unwrap_or("/");
        
        // Generate TypeScript
        format!(r#"app.{}('{}', (req, res) => {{
  res.json({{ route: '{}' }});
}});"#, method.to_lowercase(), path, path)
    } else {
        "// Invalid route\n".to_string()
    }
}
```

**Morphism:** `μ_expr→code : Literal → String (TypeScript)`

## Output: Generated Code

```javascript
// phoenix: iu_id = "user-service-api"
// Express API generated by Phoenix VCS
// Generated via: μ_config→code (Expr evaluation)

const express = require('express');
const app = express();

// List all users
app.get('/api/users', (req, res) => {
  res.json({
    route: '/api/users',
    handler: 'listUsers',
    timestamp: new Date().toISOString(),
    service: 'user-service'
  });
});

// Create a new user
app.post('/api/users', (req, res) => {
  res.json({
    route: '/api/users',
    handler: 'createUsers',
    timestamp: new Date().toISOString(),
    service: 'user-service'
  });
});

app.listen(3000);
```

## The Complete Morphism Chain

```
┌─────────────────────────────────────────────────────────────────────────┐
│                           MORPHISM COMPOSITION                            │
│                                                                           │
│   spec.md ──[μ_spec→ncl]──► spec.ncl ──[μ_ncl→config]──► BundleConfig     │
│                                                                           │
│   BundleConfig ──[μ_config→expr]──► Expr ──[eval]──► Literal              │
│                                                                           │
│   Literal ──[μ_literal→code]──► app.js (TypeScript)                       │
│                                                                           │
└─────────────────────────────────────────────────────────────────────────┘

                        μ_total = μ_literal→code ∘ eval ∘ μ_config→expr 
                                    ∘ μ_ncl→config ∘ μ_spec→ncl

Or simply:  spec.md ──[μ_total]──► app.js
```

---

## Key Properties

### 1. **Shape Preservation (Functor Law)**
The "shape" (2 routes with method/path/handler/description) flows through unchanged:
- Markdown: 2 bullet points
- NCL: 2 records in list
- BundleConfig: 2 RouteConfig structs
- Expr: 2 Record literals in List
- Code: 2 route handler functions

### 2. **Compositionality**
Each morphism is composable. The total morphism is the chain of individual morphisms.

### 3. **Bidirectional Potential**
Because we use algebraic structures (Expr/Literal) rather than strings, we can:
- Parse code back to Literal
- Apply transformations at any layer
- Verify equivalence between layers

### 4. **Traced Generation**
The comment `// Generated via: μ_config→code (Expr evaluation)` records which morphism produced the code, enabling debugging and verification.
